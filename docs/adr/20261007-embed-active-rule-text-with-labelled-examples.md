# Embed active rule text with labelled examples, and leave out archived rules

- Status: accepted
- Deciders: Anton Polkanov, Tom Iwainski, Josh Berman
- Date: 2026-10-07
- Tags: ai-chat, search, content-pipeline

## Context and Problem Statement

A rule is more than prose. It has front matter (authors, dates, redirects), good and bad examples in boxes or emails, pictures with captions, videos, and code samples. About 480 rules are archived.

Two risks shape what gets embedded. A bad example read without its label can be presented as advice. An archived rule returned in a search reads as current guidance.

What parts of a rule go into the index, and in what form?

## Considered Options

1. Embed rule text with examples labelled up front, captions for pictures, and no archived rules
2. Embed everything, including archived rules, and let the model sort it out
3. Embed prose only, leaving out examples and captions
4. As option 1, plus descriptions of pictures generated by a vision model

## Decision Outcome

Chosen option 1: "Embed rule text with examples labelled up front, captions for pictures, and no archived rules", because it keeps everything that explains a rule while making sure the model can tell a mistake from a recommendation.

What goes in:

- Title, SEO description and body text. Each chunk starts with the rule title and section heading.
- Rules are split by heading; a long section is split at paragraph breaks.
- Good, bad and OK examples start with a label, such as "Bad example (what not to do):", and stay whole in one chunk. A Markdown caption under an unlabelled example is used to label it.
- Pictures are represented by their caption, videos by their description.
- Code samples are kept as written.

What stays out:

- Authors, dates, redirects and related-rule lists.
- Archived rules. They are never embedded, and archiving a rule deletes its vectors on the next index run.

The chat prompt tells the model to mention bad examples only as things to avoid.

Running `pnpm rules-chat:index --show <rule-uri>` prints exactly what is embedded for one rule.

## Pros and Cons of the Options

### Rule text with labelled examples, captions, and no archived rules

- ✅ Keeps the examples, which often match how people describe their problem.
- ✅ The model always sees a bad example's label before the example.
- ❌ A point made only in a picture, with a thin caption, cannot be found.

### Embed everything, including archived rules

- ✅ Simplest.
- ❌ Archived guidance comes back as if it were current.
- ❌ Unlabelled bad examples can be presented as advice.

### Prose only

- ✅ Smallest index; no risk from bad examples.
- ❌ Loses the examples, which carry much of what a rule means.

### Plus vision-model descriptions of pictures

- ✅ Covers rules whose point is in a picture.
- ❌ About 5,000 images; adds indexing time and cost, and needs its own quality checks.
- Left for later, based on questions that fail because the answer was only in a picture.
